2026.08.26 · Hands-on Workbook

從 AI 教學與研究助理
到會做事的 AI Agent

本任務書不是工具說明書，而是一條可完成、可檢核、可帶走的實作路線。請沿用同一門課程、同一份研究素材或同一個真實問題完成全天任務。

上午 3 小時下午 3 小時6 位教授小班共作合成／去識別資料
Before class

開始前 5 分鐘

先完成環境確認，再進入實作。若某平台無權限，請直接切換替代路徑，不要共用帳號。

01 · 問題

選定一個真實情境

用一句話寫下：我要幫助誰，在什麼情境下，完成什麼任務。

02 · 素材

準備 3–5 份來源

課程大綱、研究摘要、評量規準、教學文件或合成資料；不要上傳可識別學生資料。

03 · 成果資料夾

集中保存證據

建立一個專案資料夾，保存提示詞、輸出、截圖、測試紀錄、已知限制與分享連結。

帳號分流：同時有 Gemini 與 ChatGPT 者走完整 A 線；只有 ChatGPT 者上午採 B 線，使用完成範例觀察、共同備課及替代成果，下午以 Codex 為主。任何情況都不交換密碼。
Morning

上午：打造 AI 教學與研究工作室

完成一個來源型工作區、一個穩定角色、一個互動原型，以及一個可分享成果。

任務 M1｜建立 Gemini Notebook（專屬私人圖書館・開卷查證法）

目標：打造專屬資料庫，就像讓 AI 開卷考試，只根據您指定的論文講義來回答，徹底告別 AI 瞎猜，每句話都能查到原文出處。

  1. 開啟 Gemini Notebook，建立您的專屬私人圖書館。
  2. 加入 3–5 份重要的講義或文獻（掌握 3-2-1 原則：少而精）。
  3. 依序詢問重點、比較兩篇異同，觀察回答後面的出處小數字標籤。
  4. 【防瞎猜測試】：故意問一個資料裡完全沒寫的陷阱題，看 AI 是否會老實說不知道。
  5. 把整理好的重點轉成教學或研究摘要。

完成證據：RAG 筆記本名稱、三個問題、至少一個可追溯引用腳註、防幻覺邊界測試紀錄、成品摘要。

開啟 Gemini Notebook使用來源包

B 線：使用來源包閱讀講師完成範例，整理「來源、問題、引用、轉化」四欄觀察表；課後取得 Gemini 權限再補做。

任務 M2｜建立專屬 Gem

🚀 未來前瞻：讓 Gem 升級成 SKILLS（專屬 Agent 工作懶人包）

線上 Gem 很方便但只能隔空文字聊天；透過「讓 Gem 升級成 SKILLS」的升級方法，可以把平常習慣的聊天指令，升級成萬用工作 SOP 懶人包（Skill），讓 AI 不只會講話，還能直接幫您讀寫電腦裡的 Word 檔、算成績統計、自動排版做出互動網頁！

📦 GitHub 升級套件（讓 Gem 升級成 SKILLS） ↗ 📺 三師爸教學影片 ↗

目標：把重複使用的教學或研究方法，保存成具有穩定角色與輸出格式的 Gem。

  1. 先填角色、任務、背景、格式四格。
  2. 加入必要限制：來源不足時承認、不得虛構學生資料、輸出標示假設。
  3. 用一個正常案例與一個反例測試。
  4. 根據失敗結果修改指令，再測一次。

完成證據：Gem 名稱、完整指令、正常案例、反例、一次修改紀錄。

建立 Gem開啟模板

B 線：將同一份四格指令放進 ChatGPT 自訂指令或專案對話，完成同樣的正常／反例測試。

任務 M3｜用 Gemini Canvas 建立互動原型

目標：把來源與教學方法轉成可操作的單頁網站。

  1. 描述使用者、學習目標、輸入、互動、輸出與限制。
  2. 要求產出單檔 HTML／CSS／JavaScript。
  3. 預覽後測試空白、長文字、手機寬度及錯誤輸入。
  4. 修正一個可見問題，留下前後畫面。

完成證據：需求提示詞、可操作原型、至少一項測試與修正。

開啟 Gemini Canvas開啟起始網站

B 線：使用 ChatGPT／Codex 修改起始網站，或以需求審查者身分完成測試清單與改版提示詞。

任務 M4｜分享或部署成果

目標：依作品型態選擇 Google Sites、GitHub Pages、EZPage 或直接分享連結。

  1. 若是課程入口與多人協作，優先評估 Google Sites。
  2. 若是 HTML／CSS／JavaScript，優先評估 GitHub Pages；若已打包完成且希望降低第一次使用 GitHub 的門檻，可改用 EZPage 上傳 ZIP。
  3. 使用 EZPage 時，確認 ZIP 根目錄有 index.html，登入前檢查授權範圍，填入網站名稱後按「部署 ZIP 檔案」。
  4. 實際開啟公開網址，走完主要流程。
  5. 檢查個資、著作權、鍵盤操作、手機版與錯誤訊息。

完成證據：公開／分享連結，或一份包含平台、步驟與限制的部署計畫。

Afternoon

下午：打造會做事的 AI 教學與研究夥伴

把上午成果放入工作區，讓 Agent 在限制內修改、測試、提供證據，再把成功流程封裝成 Skill。

任務 A1｜交辦一項清晰好驗收的研究任務（掌握 AI 的方向盤與煞車）

目標：就像帶研究生或助理，交代清楚『目標、參考素材、工作範圍、限制規範、產出格式與驗收標準』六件事。為 AI 裝上方向盤與煞車系統，讓它在安全規矩下自己跑完任務、自己檢查錯誤，交出令人滿意的成品。

完成證據：任務簡報、Agent 計畫、修改摘要、測試結果、未確認項目。

AntigravityCodex

任務 A2｜把提示詞升級成 Agent Skill

挑選一個會重複使用、具有固定步驟與驗收方法的提示詞，補上觸發情境、輸入、工作流程、限制、輸出及驗證。

完成證據：只含 `name` 與 `description` 的 YAML frontmatter、命令式流程、人工授權邊界、三個測試提示。

開啟 Skill 產生器查看骨架

任務 A2b｜驗證 Skill 能否跨平台攜帶

把剛產出的 Skill `SKILL.md` 或 ZIP 放入驗證器，檢查 frontmatter 是否只含 `name`／`description`、相對引用是否完整，以及是否誤放金鑰或本機路徑。

完成證據：驗證結果 JSON、紅黃項目處理紀錄，以及交給 Antigravity／Codex 前的人工核准。

開啟跨平台驗證器回到 Skill 產生器

任務 A3｜PIRLS 風格資料分析與簡答題初編

匯入合成資料，先做欄位、缺漏、重複與答案有效性檢查，再分析選擇題；簡答題先建立編碼規準，再交給 AI 初編並由人工覆核。

完成證據：資料品質摘要、題目答對率、AI 初編 JSON、人工最終碼與匯出 CSV。

開啟資料工作台查看治理 SOP

任務 A4｜打包 Agent 完成證據

把需求、變更、測試、畫面、已知限制與下一步整理成可交接報告。無法驗證的內容必須標示「未確認」。

完成證據：一份可下載的 Markdown／HTML 報告與附件清單。

開啟證據打包器

任務 A5｜用 123 個案例找下一個可做的題目

用一句可觀察的需求搜尋阿凱老師案例目錄，例如「簡答題編碼」、「語文創作」、「RWD 無障礙」或「GitHub 部署」，比較 2–3 張卡片後選一張做延伸。

完成證據：需求關鍵字、候選案例、工具卡片網址、直接開啟網址與選擇理由。

Fallback

卡關時不要停在原地

依序從「重試」切換到「替代路徑」，並把原因記錄為完成證據的一部分。

無法登入

改用講師完成範例、共作觀察表或同功能的另一平台；不借用他人帳號。

網路不穩

開啟本機起始包與離線工具，先完成需求、規準、測試與人工複核。

Agent 無法執行

把任務縮小成單檔、單功能、單次驗收；若仍失敗，保存錯誤與未確認狀態。

Definition of done

真正的完成，不是「AI 說完成」

最小證據組：需求簡報＋輸出檔案＋至少一項測試＋實際畫面或網址＋已知限制＋下一步。涉及學生資料時，另加去識別化與人工複核紀錄。
